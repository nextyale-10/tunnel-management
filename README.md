# SSH 隧道管理器

**独立管理常驻 SSH 隧道，不必专门留着一个 VS Code 窗口。**

这是一个 Windows 桌面应用，用于建立和维护需要长期运行的 SSH 端口转发。隧道由应用保持连接、监控状态并在断线后自动重连，VS Code 和终端会话可以独立打开、关闭或切换工作目录。

## 适用场景

你在 SSH 登录配置中设置了固定端口转发，希望多个 VS Code 窗口都能使用它，但又不希望每个窗口都重复申请同一个转发端口。过去需要留一个窗口专门维持隧道；这个应用接替那个窗口，集中维护隧道，其他窗口使用不带这组转发的配置登录。

## 功能

| 功能 | 说明 |
| --- | --- |
| 常驻隧道 | 默认关闭窗口后驻留系统托盘，隧道继续运行，不占用任务栏 |
| 多连接管理 | 同时维护多个 Host，每条连接可以独立重连和断开 |
| 端口转发 | 支持远程转发、本地转发和 SOCKS 动态代理，一个 Host 可添加多条规则 |
| 配置管理 | 新增连接、右键编辑或删除 Host，查看主配置及 Include 源文件，保存后自动刷新 |
| 普通登录配置 | 新增时同时生成 `-noforward` 别名，供终端和 VS Code 登录，避免重复申请转发端口 |
| Host 筛选 | 默认只显示带有效转发规则的 Host，可切换显示全部，并结合名称搜索 |
| 配置中心 | 集中管理关闭窗口行为、配置备份保留份数等全局设置 |
| 配置备份 | 修改配置前自动备份，也可手动备份；每个源文件默认最多保留 3 份 |
| 登录验证 | 支持密码、密钥、服务器指纹确认、私钥口令及键盘交互验证 |
| 记住密码 | 可选择保存登录密码，供下次启动和自动重连使用，也可随时清除 |
| 保活与自动重连 | 每条隧道独立设置保活间隔、未响应次数和是否自动重连 |
| 状态与日志 | 查看选中 Host 的连接状态和日志，通过“全部隧道”集中查看、断开连接 |

## 安装

从 [GitHub Releases](https://github.com/nextyale-10/tunnel-management/releases) 下载 `ssh-tunnels-<版本>-windows-x64-setup.exe`，安装后从开始菜单打开 **SSH Tunnels**。

运行环境为 Windows 10/11 x64，需要 Windows OpenSSH 客户端（支持 AskPass，8.6 或更新版本）和 .NET Framework 4。OpenSSH 客户端可在 Windows“可选功能”中安装。安装包内置 Python 和 tkinter，无需另外安装 Python。

## 开始使用

1. 打开应用，默认读取 `~/.ssh/config`；如需使用其他配置，点击“选择文件”。
2. 从左侧列表选择需要常驻的 Host，检查右侧“生效的转发规则”。列表默认只显示带转发的 Host，取消勾选“只显示带转发规则的 Host”可查看全部。如果还没有配置，可点击“新增连接”。
3. 点击“建立隧道”，按提示完成指纹确认或登录验证，等待状态变为“已连接”。
4. 按默认设置关闭窗口，应用会驻留右下角系统托盘、继续维护隧道。需要管理多条连接时，双击托盘图标恢复窗口，在“全部隧道”中查看和管理。

默认打开应用后需要手动连接。“断开此 Host”只停止选中 Host 的连接和自动重连。**默认点击主窗口右上角的关闭按钮会隐藏到系统托盘，不占用任务栏；双击托盘图标可恢复窗口，右键菜单可选择“显示窗口”或“退出应用”。** 可在配置中心将关闭按钮改为退出应用；退出会断开全部隧道。托盘图标也可能位于右下角的隐藏图标区域。

## 配置中心与备份

点击主窗口右上方的“配置中心”，按分类调整全局设置，点击“保存”后生效；点击“取消”不保存改动。

| 分类 | 设置 | 默认值与行为 |
| --- | --- | --- |
| 常规 | 关闭窗口时 | 默认最小化到系统托盘、保持连接；可改为退出应用并断开全部隧道 |
| 配置备份 | 每个源文件保留份数 | 默认 3 份，可设为 1–100 份；从下一次成功保存配置或手动备份起应用 |

“配置备份”页的“备份当前 SSH 配置”会备份主窗口选中的配置文件及其静态 Include 源文件，使用已保存的保留份数。备份不会修改源文件或重连隧道，完成后可在日志查看路径。新增、编辑或删除配置时也会自动备份。

每个源文件独立计算数量，只清理程序生成的 `源文件名.<纳秒时间戳>.bak` 备份，保留最新几份；手动命名的备份不清理。备份通常在源文件旁，如果该位置会被 Include 通配符加载，则放入旁边的 `.ssh-tunnels-backups` 目录。整次保存成功后才清理旧备份，跨文件保存失败时优先回滚。清理因权限等原因失败时会记录警告，备份可能暂时超过上限。

配置中心设置与各 Host 的保活、自动重连设置分开保存。安装版默认保存在 `%LOCALAPPDATA%\ssh-tunnels\tunnels.settings.json`，源码版在项目根目录；使用 `--app-config` 时保存在该配置文件旁的同名 `.settings.json` 文件中。设置不会写入 SSH config。

## 新增一条常驻隧道

没有现成的转发配置时，可以直接在应用中创建。例如，让远端服务器通过 `3333` 端口访问本机 `7897` 端口：

1. 点击“新增连接”，填写 Host 别名、服务器地址、SSH 端口和用户名，选择“自动”“密码登录”或“密钥登录”。
2. 在端口转发区域选择“远程转发 (RemoteForward)”，填写：

   | 字段 | 示例值 |
   | --- | --- |
   | 监听地址 | `127.0.0.1` |
   | 监听端口 | `3333` |
   | 目标地址 | `127.0.0.1` |
   | 目标端口 | `7897` |

3. 点击“添加转发规则”。需要多条转发时继续添加，再点击“保存并刷新”。
4. 在主界面选中新 Host，点击“建立隧道”。连接建立后，远端程序可通过 `127.0.0.1:3333` 访问本机的 `127.0.0.1:7897`，本机目标服务需要正常运行。
5. 普通登录使用自动生成的 `原别名-noforward`。例如新增别名为 `my-server`，终端执行 `ssh my-server-noforward`，或在 VS Code Remote-SSH 中选择 `my-server-noforward`。如使用了自定义配置文件，终端指定 `ssh -F "配置文件路径" my-server-noforward`，VS Code 也需选择同一配置文件。

保存时会同时生成两块配对配置：原别名保留填写的转发规则，`原别名-noforward` 使用相同的服务器地址、端口、用户名、登录方式和私钥设置，不复制主 Host 的预设转发规则，允许终端或 VS Code 请求自己的转发（例如 `ssh -D`）。即使未填写转发规则，也会生成这两块配置。后续在界面编辑任一块时会同步已有配对的公共配置和别名；删除仍只作用于所选 Host。

两块配置会先一起校验，再备份原文件并一次写入、刷新列表；任一别名已存在于主配置或 Include 文件中，或配置在保存期间被外部修改，都会停止保存并提示，不覆盖已有内容。已有隧道继续运行。新增主 Host 默认包含 `ExitOnForwardFailure yes`；普通登录 Host 不生成 `ExitOnForwardFailure` 或 `ClearAllForwardings`。两者均包含 `ServerAliveInterval 30`。备份文件位于原配置旁，名称为 `config.<时间戳>.bak`。

`-noforward` 表示不复制主 Host 的预设转发，并不隔离 `Host *`、Include 等匹配配置。如果普通登录别名仍有预设转发或 `ClearAllForwardings yes` 生效，列表下方、Host 详情和日志会提示检查源配置；请按需要调整公共规则的适用范围。程序不会自动修改公共配置，也不会用全局清除转发的方式覆盖它们。`ClearAllForwardings yes` 会同时清除配置文件和命令行请求的转发，可能影响 VS Code 的连接，详见 [OpenSSH 文档](https://man.openbsd.org/ssh_config#ClearAllForwardings)。

## 筛选左侧 Host 列表

- 每次打开程序，默认勾选“只显示带转发规则的 Host”；取消勾选显示全部 Host。没有有效转发规则的 `-noforward` 默认隐藏，继承了转发规则的仍会显示。
- 筛选依据 OpenSSH 解析后的有效规则，支持从 `Host *`、Include 等配置继承的本地转发、远程转发和动态代理；被 `ClearAllForwardings yes` 清除的规则不计入。
- 名称搜索与筛选开关同时生效，列表下方显示当前可见数量和总数。读取失败的 Host 会计入错误提示，切换显示全部后可选中查看错误。
- 切换筛选只改变列表显示，不修改配置、不连接或断开隧道。普通登录 Host 可查看、编辑和删除；没有有效转发规则时，应用内“建立隧道”按钮保持禁用。实际登录请使用终端或 VS Code。

## 编辑、删除与查看源配置

- **右键左侧 Host**：连接／重新连接、断开、编辑、删除或查看源配置；键盘也可按 `Shift+F10` 打开菜单。
- **编辑 Host**：打开该 Host 的原始配置段，可修改首行别名、地址、用户名、端口、转发和高级选项，不添加新的 Host／Match／Include 分段。其他 Host 的配置、注释及文件格式保持原样。
- **配对同步**：已有 `A` 和 `A-noforward` 时，编辑任意一块的公共配置都会同步另一块。包括地址、用户、端口、认证、私钥、保活和高级选项，以当前窗口保存的内容为准；另一块独有的公共参数会被替换或删除，注释保留。`A` 独立保留转发规则，`A-noforward` 不允许在块内添加预设转发，但允许客户端请求转发。保存任一侧会移除普通登录配对块中遗留的 `ClearAllForwardings`，保留其行尾注释；不会添加或恢复该项，也不会覆盖主 Host 自己的该项设置。
- **转发失败策略**：`ExitOnForwardFailure` 不参与公共参数同步，主 Host 可独立修改或删除该项；普通登录端的缺失、删除或修改不会影响主 Host。旧普通登录块遗留的该项和注释保留原样，不批量清理。应用建立隧道时仍通过命令行强制 `ExitOnForwardFailure=yes`；配置文件中的值供应用外直接调用 SSH 时使用。
- **同步改名**：将 `A` 改成 `B` 会同时将已有的 `A-noforward` 改为 `B-noforward`；从普通登录端改名时需保留 `-noforward` 后缀。新名称与已有配置或运行中的隧道冲突时拒绝保存。当前进程保持运行，界面状态和后续自动重连使用新别名；目标地址、端口和用户不变时复用已保存密码，登录目标改变时重新验证。
- **共享别名**：对于 `Host alpha beta` 这类普通共享块，编辑 alpha 时会分离为独立配置，beta 保留原配置；删除 alpha 只移除它的别名。
- **删除 Host**：需要确认；同一文件中的重复定义一起删除。正在运行、连接中或等待重连的 Host 必须先手动断开，程序不会因删除配置而自动停止隧道。
- **查看配置**：点击顶部“查看配置”可只读查看当前主配置及静态 Include 文件；Host 右键“查看源配置”会定位并高亮对应配置段，支持选中文字后复制。

编辑、删除都会先用隔离副本校验，再备份并替换源文件；如果主配置或 Include 文件在编辑期间被其他程序修改，则拒绝覆盖。配对位于不同源文件时会一起校验并逐个保存，某个文件写入失败时尝试回滚已写文件；若回滚也失败，会列出备份路径。编辑后当前连接继续使用原参数，后续连接使用新配置；正在连接或等待认证时需完成后再保存。源文件查看窗口显示打开时的快照，重新打开可刷新。

只同步已经存在、名称按 `A` / `A-noforward` 对应的配对；旧配置缺少其中一块时不自动补建。同步发生在应用内编辑保存时，外部编辑文件后刷新列表不会自动改写另一块。配对中的每个别名需有一块独立定义；存在多处定义或两个配对别名共用一个 Host 块时，先整理后再同步。未配对 Host 的多处定义仍可逐段编辑，改名时会更新它的所有显式定义。

为避免影响其他 Host，与通配符／排除规则共用的块、块内含 Include 的配置仅支持查看；同一别名跨多个文件的删除会被拒绝。改名时若发现 ProxyJump／ProxyCommand／Match／Include 引用旧别名，也会提示先处理引用。此类复杂配置可根据源文件路径在外部编辑器中处理，再点击“刷新 Host”或按 `Ctrl+R`。

## 连接与密码

在主界面可以为选中 Host 调整保活间隔、未响应次数及“断线自动重连”，这些设置在下一次连接时生效。“断线自动重连”以空框表示关闭、对勾表示开启。新建 Host 的保活间隔为 30 秒；普通断线会按设置自动重连，最终认证失败或取消验证后停止自动重试，可在处理问题后手动连接。

“已连接”表示 SSH 和转发监听已建立，目标端口上的服务还需要正常运行。需要排查时，查看当前 Host 的日志或点击“打开日志”。

| 验证信息 | 保存方式 |
| --- | --- |
| 普通登录密码，勾选“记住密码” | 认证及转发成功后保存到当前 Windows 用户的凭据管理器，下次启动和自动重连可复用 |
| 普通登录密码，未勾选 | 仅在本次运行中缓存，退出后清除 |
| 私钥口令、验证码、服务器的键盘交互提示 | 仅用于本次验证 |
| 配置了 `ProxyJump` / `ProxyCommand` 的连接 | 支持交互，暂不保存或自动填充密码 |

密码不写入 SSH 配置、界面偏好、命令行或日志。点击“清除历史密码”可清除当前 Host 的已保存密码和运行内缓存。服务器指纹由 OpenSSH 按现有配置校验，应用在需要时弹窗确认。

安装版的设置、运行状态和日志保存在 `%LOCALAPPDATA%\ssh-tunnels\`；源码版的设置和运行状态保存在项目目录。升级或卸载会保留用户数据、SSH 配置和已保存密码，需要清除密码时可先使用“清除历史密码”。

## 从源码运行

需要 Python（包含 tkinter，建议 Python 3.12）、Windows OpenSSH 和 .NET Framework 4；无需安装第三方 Python 包。

```powershell
python ssh_tunnels.py --gui
```

Python 的 `pythonw.exe` 在 PATH 中时，也可以双击 `start.bat` 或 `start-silent.vbs`。
